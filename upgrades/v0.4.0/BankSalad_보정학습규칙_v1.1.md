# BankSalad 보정 학습 규칙 v1.1

## 목적
2026-09-07 첫 주간 반영에서 사람이 수정한 거래를 분석해, 다음 실행부터 자동확정률을 높이되 오분류 위험이 큰 패턴은 검토 큐에 남긴다.

## 설계 원칙
1. **과거 확정은 다시 흔들지 않는다.** 사용자 확정 거래는 `source_key_overrides`로 고정한다. `source_key_version=v1`은 호환성 키이므로 기존 이력을 유지하는 동안 변경하지 않는다.
2. **일반화는 충분히 식별 가능한 패턴만 한다.** merchant 이름 하나만으로 성격이 달라질 수 있으면 자동확정하지 않는다.
3. **거래 총액과 세부 카테고리를 분리한다.** 지출임은 확실하지만 세부 품목이 불명확한 경우 지출액은 반영하되 `검토 필요`로 남긴다.
4. **미매칭 이체는 손익을 만들지 않는다.** 특히 카카오페이/네이버페이 단독 이체는 충전·송금·실제 소비가 모두 가능하므로 상대 거래가 없으면 손익 0으로 검토한다.
5. **반복 PG 결제는 금액+원본카테고리+결제수단까지 묶어서 학습한다.** PG사명만으로는 자동분류하지 않는다.

## 자동확정 우선순위
프로그램은 다음 순서로 판단한다.

1. `source_key_overrides`: 과거 사용자 확정값 재생
2. `learned_rules`: 반복성이 검증된 사용자 규칙
3. 내부이체 페어링: 동일일·동일금액·±2초·반대부호
4. Finance OS merchant override
5. BankSalad 원본 카테고리 매핑
6. 그래도 불명확하면 `검토 필요`

이 순서 때문에 향후 분류규칙이 바뀌어도 과거 확정 거래는 재처리 시 변하지 않는다.

## 자동화하지 않는 패턴
다음은 원본 XLSX 정보만으로 경제적 성격을 안정적으로 구분할 수 없으므로 merchant-only 학습을 금지한다.

- **쿠팡_쿠페이**: 식료품과 가전이 같은 merchant로 유입됨.
- **카카오페이 미매칭 이체**: 실제로 술·유흥과 외식이 같은 raw pattern으로 확인됨.
- **편의점**: 간식과 주류를 merchant만으로 구분 불가.
- **일반 PG사**: 나이스정보통신 등은 여러 서비스를 중계하므로 merchant만으로 서비스명을 추론하지 않음.

## 신규 키워드 학습
원본 메모 또는 향후 주문상세가 들어오는 경우 다음 키워드를 활용한다.

- 주류: `맥주`, `소주`, `와인`, `주류`, `하이볼`, `막걸리` → `술·사교 / 술·유흥`
- 식재료: `두부`, `현미밥`, `발아현미`, `특란`, `계란`, `달걀`, `닭가슴살`, `식재료` → `식비 / 장보기·집밥재료`
- 가전: `가습기`, `공기청정기`, `청소기`, `선풍기`, `전자레인지` → `생활용품 / 가구·가전`

키워드는 merchant보다 우선하지만, 과거 `source_key` 확정보다 낮은 우선순위다.

## 운영 KPI
매주 Import Log에서 최소 다음을 본다.

- 신규 거래 수
- 자동확정 수
- 검토 필요 수
- 잠정 수
- 검토율 = 검토 필요 / 신규 거래
- 사용자 보정 후 최종 확정률

첫 보정 주간 기준: **신규 19건 → 최종 확정 19건 / 검토 0 / 잠정 0**.

## 향후 학습 승격 기준
새로운 보정이 들어왔을 때:

- 동일한 merchant/금액/원본카테고리/결제수단 조합이 **2회 이상 같은 의미**로 반복되면 `learned_rules` 후보.
- 한 번이라도 서로 다른 의미가 나오면 merchant-only 규칙 금지.
- 구독처럼 월 반복이 예상되는 경우 금액이 바뀌면 자동확정하지 않고 다시 검토.
- 사용자가 제공한 품목명은 과거 거래의 `source_key` 확정에는 즉시 저장하되, 미래 일반화는 키워드 수준으로만 적용.
